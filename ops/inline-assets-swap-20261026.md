# Inline Assets swap — 2026-10-26

## Delivered source

Assets → Swap opens a panel inside the selected portfolio instead of navigating to Trade. A connected Wallet Standard external wallet can review SOL ↔ USDC, explicitly approve, sign the exact validated message and submit once. The shared private provider module owns the one-use grant maps. No injected global provider, seed import or sign-and-send shortcut is used.

Reviews show token amounts, protected minimum, SOL network fee and account rent. The 0.5% slippage limit and short expiry are enforced by the existing engine. Input changes, account/provider changes, expiry and hidden-document transitions invalidate approval. Signature verification and strict simulated effects remain mandatory. Ambiguous submission stays durably pending; the status action never resends. Verified finalized success requests a common balance refresh.

The inline confirmation holds a same-origin per-wallet Web Lock across review authorization, wallet prompt and submission. Shared futures entry/close authorization checks the swap journal under the same lock before claiming a signing operation. Inline swap checks their durable pending journals before review and again before/after the prompt. Missing lock support blocks inline signing. The public trading projection includes pending swaps.

## Explicit limitations

- Native Android still uses its existing secure native swap entry.
- A remembered Phantom public address must be reconnected to obtain actual signing capability.
- A watch-only linked address cannot sign, even after Google login.
- The server-custodied bot wallet 3AXF…bQ5T still needs its dedicated authenticated manual-swap server flow. This change does not deliver that flow or permit another wallet to sign it.
- No transfers between bot/native/Phantom accounts, bot activation, actual wallet signatures or financial submissions were performed for verification.
- No Android APK is generated by a web deployment.
